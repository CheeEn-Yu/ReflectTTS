# ReflectTTS

[![Conference](https://img.shields.io/badge/SLT-2026-blue)](https://attend.ieee.org/slt-2026/)

Official code for **“Listen, Critique, and Refine: RL-Based Self-Refinement for
Instruction-Following Speech Synthesis”**
The method trains one Step-Audio-2-mini model with GRPO to synthesize a first
attempt, listen to it, write a textual critique, and synthesize a refined
attempt. The complete trajectory stays in one interleaved text/audio token
stream.

```text
instruction + text -> v1 audio -> self-critique -> v2 audio
```

## Repository contents

| Path | Purpose |
| --- | --- |
| `data_preprocess/` | Download ParaSpeechCaps metadata and build two-hop RL examples |
| `train/rl/` | Prompt, rollout, reward, and GRPO components |
| `train/rl_vllm/` | Paper training path: vLLM rollout sidecar and weight synchronization |
| `infer/` | One-hop and generate-critique-refine inference |
| `clsp_eval/` | CLSP style-adherence and Whisper WER evaluation |
| `speaker_rag/` | Gender filtering and CLSP reranking of vocoder reference speakers |
| `ablation/` | Critique-content and base/RL model ablations from the paper |
| `scripts/` | Reproducible data, Slurm training, inference, and evaluation entry points |

## Requirements

- Linux, CUDA GPUs, Conda, and Slurm for the supplied job scripts.
- Two high-memory GPUs for the paper training setup: one for the policy,
  token2wav, Whisper-large-v3, and CLSP; one for the vLLM rollout sidecar. The
  paper experiments used two NVIDIA H200 GPUs.
- [Step-Audio-2](https://github.com/stepfun-ai/Step-Audio2) source and the
  `Step-Audio-2-mini` checkpoint at `Step-Audio2/Step-Audio-2-mini`.
- vLLM in a separate Conda environment. The launcher uses an environment named
  `vllm` by default; override it with `VLLM_ENV=<name>`. Its vLLM build must
  support `worker_extension_cls`. The main `step` environment intentionally
  stays separate because vLLM and Step-Audio-2 need different dependency sets.

Create the main environment and place the external code as follows:

```bash
conda env create -f environment.yml
conda activate step
git clone https://github.com/stepfun-ai/Step-Audio2.git Step-Audio2
```

Follow Step-Audio-2's instructions to download the checkpoint into the path
above. For one-hop inference through Singularity/Apptainer, build the Stepfun
image described in `scripts/infer/run_vllm_server.singularity.sh`.

`yfyeung/CLSP`,
`openai/whisper-large-v3`, ParaSpeechCaps metadata, and InstructTTSEval parquet
files are downloaded from Hugging Face when first used.

## Training

Run commands from the repository root. First prepare ParaSpeechCaps prompts and the first-pass tokens, critiques, CLSP baselines, and WER baselines:

```bash
huggingface-cli login  # accept the ParaSpeechCaps license first
SPEAKER_RAG=1 \
  sbatch -A <account> scripts/data/build_rl_data.sbatch
```

The default data job reproduces the paper selection: seed-0 random sampling of
1,000 training prompts followed by removal of rows with `WER(v1) > 0.10`.
Change `TRAIN_SAMPLE_SIZE`, `DATA_SEED`, or `MAX_WER_V1` only for an ablation.

The default output used by the training jobs is
`data/rl/paraspeechcaps_en_twohop/train.jsonl`. A row has this shape:

```json
{
  "uid": "example-id",
  "instruction": "Speak quickly with an urgent, assertive tone.",
  "text": "Text to synthesize.",
  "lang": "en",
  "v1_tokens": [151696, 151702],
  "critique": "(i) ... (ii) ... (iii) ...",
  "clsp_v1": 0.51,
  "wer_v1": 0.0,
  "clsp_v1_reference": "default_female.wav"
}
```

Build the Qwen2 view consumed by the rollout sidecar once, then start training:

```bash
sbatch -A <account> scripts/train/build_qwen2_view.sbatch

# Short end-to-end check before committing a full allocation.
STEPS=3 LIMIT=8 G=4 ON_POLICY_CRITIQUE=1 SPEAKER_RAG=1 \
  sbatch -A <account> -p <dev-partition> -t 00:50:00 \
  scripts/train/run_rl_twohop.sbatch

# Paper setting: precomputed v1, on-policy critique, and GRPO on v2.
STEPS=1000 G=16 ON_POLICY_CRITIQUE=1 SPEAKER_RAG=1 \
  sbatch -A <account> scripts/train/run_rl_twohop.sbatch

# Paper's one-hop RL baseline
SPEAKER_RAG=1 \
  sbatch -A <account> scripts/train/run_rl_onehop_baseline.sbatch
```

The two-hop launcher uses two GPUs: the `step` environment owns the trainable policy and frozen reward models, while the vLLM environment owns the rollout sidecar. `CRITIQUE_MODE=static` is the paper mode: `v1` is precomputed, and `ON_POLICY_CRITIQUE=1` replaces the stored critique with one generated by the current policy before each v2 rollout. The name `static` means the resulting critique is prompt context and does not receive policy-gradient updates.

For the more expensive fully on-policy research variant, use
`CRITIQUE_MODE=self ON_POLICY_V1=1 ON_POLICY_CRITIQUE=0`; this generates v1 and the critique during training, and includes the critique plus v2 in the trained completion. This is not the paper configuration.

Check progress in `out/slurm/rl_vllm_twohop_<job-id>.out` and the sidecar log in
`out/slurm/sidecar_<job-id>.log`. Checkpoints are saved below
`out/rl/vllm_twohop/run_<job-id>_nccl/`. Requeueing the same Slurm job resumes from the highest `ckpt-step*/adapter` in that directory; for a new job ID, set `OUT_DIR` to the previous run directory to resume there.

Use a saved two-hop adapter for generate-critique-refine inference:

```bash
ADAPTER=out/rl/vllm_twohop/<run>/ckpt-stepNNN/adapter \
SPEAKER_RAG=1 \
  sbatch -A <account> scripts/infer/run_twohop_infer.sbatch
```

The same launcher can be run with `bash` inside an interactive two-GPU Slurm
allocation. It refuses to run when `SLURM_JOB_ID` is absent, which prevents an
accidental model launch on the login node:

```bash
srun -A <account> -p dev -t 00:50:00 --gpus-per-node=2 --pty bash

# Now on the allocated compute node:
cd /path/to/listen-critique-refine
ADAPTER=out/rl/vllm_twohop/<run>/ckpt-stepNNN/adapter \
TAG=my_twohop_smoke LIMIT=20 SPEAKER_RAG=1 VLLM_ENV=vllmomni \
  bash scripts/infer/run_twohop_infer.sbatch
```

The job writes `v1.jsonl`, `v2.jsonl`, generated WAV files, and CLSP/WER
summaries below its output directory. The frozen zero-shot and one-hop RL
baselines use:

```bash
OUT_DIR=out/eval/zero_shot SPEAKER_RAG=1 \
  sbatch -A <account> scripts/infer/run_onehop_infer_zeroshot.sbatch

TRAIN_OUT=out/rl/vllm_onehop/<run> EVAL_OUT=out/eval/onehop_rl \
  sbatch -A <account> scripts/infer/run_onehop_infer_rl.sbatch
```

The Table III two-hop path generates the critique in a turn-2 `<think>` block,
then continues with `<tts_start>` and the refined audio. The paper training path
uses a separate structured critic call and injects that critique as prompt
context for the rewarded v2 rollout. Both calls use the same synchronized policy,
but the two critique prompt scaffolds are different; use the `trained` mode in
`ablation/infer_ablation_pipeline_vllm.py` to evaluate the structured-prompt path.

## Evaluation

Score a two-hop output directory, a single result file, or the ground-truth
topline with the same evaluator:

```bash
OUT_DIR=out/full_eval_vllm/<run> \
  sbatch -A <account> scripts/eval/run_clsp_score.sh

INPUT_JSONLS="out/eval/zero_shot/results.jsonl" \
EXPECTED_PER_TASK=1000 \
  sbatch -A <account> scripts/eval/run_clsp_score.sh

SPLIT=en OUT_DIR=out/eval/gt \
  sbatch -A <account> scripts/eval/download_gt_audio.sbatch
# After the download job finishes:
INPUT_JSONLS="out/eval/gt/results.jsonl" \
EXPECTED_PER_TASK=1000 \
  sbatch -A <account> scripts/eval/run_clsp_score.sh
```

The Gemini 2.5 Pro evaluation comes from InstructTTSEval. Clone that repository
beside the paths expected by the wrapper, then export an API key:

```bash
git clone https://github.com/KexinHUANG19/InstructTTSEval.git
GENAI_API_KEY=<key> INPUT_JSONL=<results.jsonl> \
  sbatch -A <account> scripts/eval/run_gemini_eval.sh
```

The CLSP and Gemini wrappers require complete inputs by default. Full English
paper runs must contain 1,000 valid audio files for each of APS, DSD, and RP;
smoke or custom runs can set `EXPECTED_PER_TASK=<N>`.

Table VI is a five-rater human study over 120 samples. It is a data-collection
protocol rather than an automatic metric and is not implemented by these scripts.

See [ablation/README.md](ablation/README.md) for the critique-content and model
ablations, and [speaker_rag/README.md](speaker_rag/README.md) for reference
speaker retrieval.
